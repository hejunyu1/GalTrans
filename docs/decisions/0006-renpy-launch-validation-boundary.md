# 0006：只在完整临时副本中启动 Ren'Py 并观察真实窗口

- 状态：已接受
- 日期：2026-08-18

## 背景

lint 和独立 compile 已证明导出脚本能被 Ren'Py 8.5.3 解析与编译，但不能证明图形运行时能够
加载项目并建立显示窗口。直接从安装 SDK 或输入项目启动会产生缓存、日志、存档、编译物和可能
的截图；普通超时后只终止父进程也可能留下子进程。CI 通常没有真实 SDK 或交互式图形桌面。

## 决定

启动验证复用 ADR 0005 的三个只读输入和完整临时边界：完整复制 SDK，只复制项目源脚本，并把
独立导出的 `game/tl/<language>` 合并到临时项目。安装 SDK、输入项目和导出目录都不传给图形
进程，验证前后复核项目与导出文件哈希。

唯一允许的图形命令是：

```text
<临时 SDK>/renpy.exe <临时项目> run --savedir <临时存档目录>
```

`RENPY_LANGUAGE` 固定为目标语言，`APPDATA`、`LOCALAPPDATA`、`TEMP` 和 `TMP` 都指向临时根，
音频使用 dummy 驱动。stdout/stderr 写入临时根；Ren'Py 日志、缓存、编译物、存档和可能的截图
只能出现在临时 SDK、项目、存档或隔离用户数据目录。

GalTrans 只在临时项目写入保留脚本 `_galtrans_launch_validation.rpy`，把窗口关闭配置为
`Quit(confirm=False)`，避免最小样例依赖完整退出确认界面。若输入项目已经占用该路径则拒绝
启动。该脚本不生成窗口，也不提供成功信号。

启动成功和基础显示成功必须同时满足：进程未提前退出，并且属于该进程的顶层窗口连续稳定可见、
客户区宽高均大于零。只有退出码 0、进程存活或日志文本都不足以通过；出现 `traceback.txt`、
`errors.txt` 或已知致命输出时，即使窗口可见也失败。此证据不做截图、像素比较或 OCR。

显示成功后先发送窗口关闭请求并等待正常退出；未按时退出则依次调用 terminate 和 kill。进程从
创建后立即加入带 `KILL_ON_JOB_CLOSE` 的 Windows Job Object，收尾时显式终止 Job 并查询到活动
进程数为零后才关闭句柄。显示前以 0 正常退出仍失败；显示稳定后自行以 0 退出可以通过，非零
退出失败。

CI 使用受控的 SDK 进程、窗口探针和 Job Object 替身，验证精确命令、路径隔离、窗口证据、提前
退出、超时升级、致命错误和无残留进程边界，不要求真实 SDK 或图形桌面。真实 SDK 验证仅在有
Windows 桌面的本机执行。

## 结果

V0.2 可以证明自制 source-only 样例与独立导出在指定 SDK 中 lint、独立编译，并以目标语言建立
真实非零窗口，且所有受 GalTrans 控制的运行产物和进程都被临时边界收口。完整 SDK 复制仍有
时间和磁盘成本。

这不证明窗口中的具体译文、字体、像素、文本溢出、菜单交互或完整路线正确，也不授权处理真实
游戏。后续更强的画面或交互自动化必须另立边界，不能把本决策的窗口证据解释为视觉内容正确。
