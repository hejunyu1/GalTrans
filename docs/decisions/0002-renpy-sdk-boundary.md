# 0002：在 source-only 临时副本上调用 Ren'Py SDK

- 状态：已接受
- 日期：2026-08-18

## 背景

V0.1 的保守提取器需要用 Ren'Py 官方行为交叉验证，但官方 `translate`、`lint` 和编译过程会
产生翻译目录、缓存、存档、日志和 `.rpyc`。直接在输入项目上运行这些命令会破坏只读边界。

本机 Ren'Py 8.5.3 的独立 `compile` 还会强制尝试重编译 SDK 自带的 `renpy/common`。SDK
不可写时会打印多条权限异常，但进程仍可能返回退出码 0，因此只检查退出码不可靠。

## 决定

GalTrans 接受 SDK 目录或 `renpy.exe`，但只在同时含有 `renpy.exe`、`renpy.py` 和 `renpy`
目录时将其识别为 SDK 根目录。存在多个候选时拒绝猜测。

当前边界只允许：

1. 用 `--version` 做无项目的版本探测；
2. 把输入项目 `game` 下非 `tl` 目录的 `.rpy/.rpym` 复制到系统临时目录；
3. 在该临时项目上运行官方 `translate <language>` 与 `lint`，并把存档目录也指向临时位置；
4. 比较 GalTrans 提取数量与官方模板数量；
5. 将非零退出码或输出中的 Traceback、文件和权限异常视为失败。

SDK 不接收输入项目路径。独立 `compile`、正常 `run`、翻译写入和图形自动化不属于此增量。

## 结果

官方工具的所有项目侧写入都随临时目录清理，输入源文件在调用前后以 SHA-256 再次确认。
测试可以用受控的 SDK 进程替身验证路径隔离、生成结构和错误处理，而 CI 不依赖本机 SDK。

当前比较只覆盖官方翻译块与 `old` 字符串的数量，不能证明文本、标记或复杂语法完全等价。
后续导出里程碑必须增加逐条标识与受保护标记验证，不能把本决策的数量一致性当成导出许可。
