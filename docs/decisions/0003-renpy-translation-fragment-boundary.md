# 0003：从官方语句骨架渲染 Ren'Py 翻译片段

- 状态：已接受
- 日期：2026-08-18

## 背景

逐条交叉验证已经能把 GalTrans 文本段对应到官方翻译 ID 和 `old` 字符串。下一步需要建立
确定性的官方格式生成边界，但直接重建角色名、属性、语句后缀或引号会放大保守提取器的语法
盲区。此时直接写出完整翻译目录也会把片段生成、路径规划、覆盖策略和 SDK 验证混在一起。

## 决定

官方模板读取器为受支持的单语句条目保留 Ren'Py 生成的原语句和唯一字符串范围。逐条映射同时
携带从 GalTrans 文本段取得的受保护标记。纯内存渲染接口接收一条已匹配记录、目标文本和语言
名，并在输出前验证：

1. 原语句中的字符串仍与交叉验证记录一致；
2. 目标文本不含原始换行或 NUL；
3. 插值、文本标签和转义标记与原文完全一致且顺序不变；
4. 目标文本可以作为原引号类型的单个 Ren'Py 字符串安全解析；
5. 台词和旁白必须有官方翻译 ID，菜单必须保持官方 `old` 字符串结构。

台词和旁白返回完整的 `translate` 块。菜单返回缩进后的 `old/new` 条目，并明确标记后续写出器
必须把它放进唯一的 `translate <language> strings:` 容器。接口不写文件；本增量不定义或接入
模型响应，未来模型结果仍必须先经过独立的结构校验才能调用此接口。

## 结果

角色名、属性和语句后缀直接沿用官方模板骨架，确定性代码只替换已确认的唯一字符串。目标文本
使用与当前中间格式一致的 Ren'Py 源字符串正文表示；若包含与外层相同的引号，调用方必须显式
转义，渲染器不会猜测意图。

后续目录导出必须先聚合同一模板文件中的片段，为菜单建立单一 strings 容器，并以新文件模式
写入独立输出根目录。覆盖策略、完整文件组装和 SDK 编译验证不属于本决策的当前增量。
