# 0017：用 Tkinter 和类型化进度连接最小 Windows 玩家界面

- 状态：已接受
- 日期：2026-08-25

## 背景

V0.3 已能从 source-only Ren'Py 项目自动翻译到经过 SDK lint/compile 的全新补丁目录，但唯一入口
仍是带多个参数和环境变量的命令。用户希望先快速得到无人逐条审阅、普通玩家大致可用的版本，
再改善质量和高级能力。当前项目坚持标准库基础，尚没有足以证明必须引入 Web 框架或桌面框架的
需求。

界面不能让耗时的 SDK 和网络调用阻塞 Windows 消息循环，也不能复制或绕过现有确定性边界。
API key 不能因从环境变量改为输入框，就进入日志、SQLite、SDK 子进程或长期界面状态。

## 决定

第一版玩家界面使用 Python 标准库 Tkinter。它收集 Ren'Py SDK、带源脚本的项目、尚不存在的
输出目录、Chat Completions endpoint、模型和 API key，然后直接调用 V0.3 的自动应用服务。
工作区继续由输出路径确定，原项目只读、结构化 Provider、提案验证、质量报告、临时写出和
SDK lint/compile 边界均保持不变。

自动应用服务增加只读的类型化进度回调，稳定报告以下阶段：路径预检、提取、SDK 交叉检查、
批次翻译、确定性质量检查、渲染、导出验证、发布和完成。批次进度只包含完成数和总数，不包含
游戏文本、Provider 响应或凭据。CLI 不需要订阅该回调，保持现有行为兼容。

完整自动流程在一个后台线程中串行执行。后台线程只把进度、成功或已隐藏凭据的失败事件放入
线程安全队列；Tk 主线程定时取出事件并更新控件，从不等待或 `join` 后台线程。运行时禁用配置
和开始按钮，成功与失败都恢复。第一版不提供强制取消，因为同步 Provider 请求的结果可能不确定；
杀死线程后自动重提可能造成重复费用，Python 线程也没有安全强制终止机制。

API key 直接从输入控件复制到内存请求对象，不写入进程环境。点击开始后输入控件立即清空；
Worker 完成后释放请求引用。进度和正常错误不包含 key，意外异常文本也会按实际 key 值替换。
界面不会把 key 传给 SDK 参数、工作区、SQLite 或输出。

## 推迟

本增量不实现 Windows 安装包、自动下载或发现 SDK、普通成品 `.rpa/.rpyc`、本地 API、Web UI、
自动启动游戏、完整游戏副本组装、费用统计、Provider 账号管理、人工逐条审阅、自动语义审校或
强制取消。真实商业 Provider 仍未用用户凭据和费用验证。

## 结果

用户现在可以通过一个窗口启动已有自动翻译流程并看到阶段和批次进度，无需拼写翻译命令；
界面卡顿、凭据进入环境和界面层复制核心逻辑的风险被限制。代价是当前仍需仓库 Python 环境、
Ren'Py SDK 和用户自己的兼容 Provider 配置，还不是可分发给普通玩家的安装版。

Tkinter 是当前最小、可逆的交付选择，不把未来 UI 技术锁定为桌面或 Web。若玩家测试证明布局、
安装、异步任务或可访问性需要更强框架，可在保持应用服务和进度 schema 的前提下替换界面层。
