# 0004：只向全新独立目录发布 Ren'Py 翻译文件

- 状态：已接受
- 日期：2026-08-18

## 背景

单条翻译片段已经可以在内存中安全生成，但 Ren'Py 要求同一模板文件中的菜单字符串位于一个
`translate <language> strings:` 容器中。把片段直接逐条追加到目标文件会产生重复容器，也会
引入部分覆盖、路径穿越和失败后留下混合版本的风险。

## 决定

导出器先在内存中按官方模板相对路径分组片段。台词和旁白保持官方块形式，菜单条目统一放在
该文件末尾的单一 strings 容器中。导出文件路径固定为：

```text
<output>/game/tl/<language>/<official-template-path>
```

模板路径必须是无空段、`.`、`..`、驱动器标记或绝对前缀的 `.rpy` 相对路径。重复文本段 ID、
重复官方翻译 ID、重复输出路径、片段语言不一致或片段结构不一致都会导致整个导出被拒绝。

写出时要求输出根目录完全不存在，并拒绝与输入项目互为祖先或后代的路径。文件先写入输出根
同一父目录下由系统创建的唯一暂存目录，使用 UTF-8 BOM 和 LF；全部成功后再重命名发布。
当前 Windows 范围内，目标在发布前再次检查，既不提供覆盖参数，也不合并已有目录。

## 结果

输入项目路径只用于隔离检查，不参与写入。旧输出目录及其中任何文件保持不变；失败的暂存目录
会被清理，成功发布的目录不会再进入清理分支。输出内容不包含官方生成器的时间戳 TODO 注释，
因此相同片段可产生可重复比较的文件内容。

此边界不负责取得译文，也不证明调用方提供的片段覆盖所有源文本。后续命令层必须使用经过结构
校验的译文输入，并在可写项目副本上通过 SDK 编译或 lint 后，才能把目录视为可运行补丁。
