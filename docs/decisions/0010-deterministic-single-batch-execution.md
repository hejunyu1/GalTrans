# 0010：由 GalTrans 每次执行并持久化一个翻译批次

- 状态：已接受
- 日期：2026-08-20
- 后续：ADR 0012 保留单批次检查点所有权，并用持久化 Provider 回执替代无法消歧的直接重放。

## 背景

ADR 0008 定义了翻译后端、提案验证和任务状态，ADR 0009 可以原子保存检查点与提案正文，但
两者尚未连接成执行流程。调用方若自行安排状态转换，可能在记录 `running` 前调用后端、忘记
保存失败、重复执行已完成批次，或把未经当前引擎验证的结果交给存储层。

在接入真实模型、缓存或 Agent Harness 前，GalTrans 需要先拥有一个完全确定性、可由 CI 替身
驱动的最小执行边界。它必须证明进程关闭和后端失败不会破坏输入项目或持久化事实来源。

## 决定

### 每次只执行一个批次

`TranslationTaskRunner.run_next_batch` 每次从 SQLite 重新读取任务和检查点，并按任务中的固定顺序
选择第一个 `pending` 批次。调用后端前，它先通过比较交换把该批次保存为 `running` 并增加一次
尝试次数。只有这次提交成功后，筛选后的 `TranslationBatch` 才会传给 `TranslationBackend`。

执行器不接收游戏路径、SDK、导出目录或文件访问能力。后端仍只能返回
`TranslationProposal` 元组，不能写数据库或推进状态。

### 成功、失败和原子性

后端返回的每条提案先经过调用方提供的确定性引擎验证器。只有批次中的每个文本段恰好有一个
有效提案，执行器才构造完成检查点，并让 `TranslationStore` 在同一事务中再次验证和保存提案
正文与检查点引用。

后端异常、返回类型错误、提案缺失、重复或来源与标记验证失败时，执行器从已保存的 `running`
检查点构造 `failed` 检查点，保存有界错误摘要，不保存任何提案正文。若另一个执行者已经改变
检查点，比较交换拒绝迟到的完成或失败结果；执行器不能覆盖较新的暂停、恢复或完成状态。

### 暂停、恢复和重放

执行器提供显式的暂停、失败恢复和中断恢复操作，它们都通过存储层原子提交。数据库中存在
`running` 批次时，普通执行调用拒绝猜测该批次是否仍有活动执行者，必须先显式恢复。完成任务
重复执行只返回当前检查点，不再调用后端。

每次只处理一个批次使调用方可以在批次之间停止进程并稍后重开数据库继续。若进程在记录
`running` 后、保存完成结果前退出，恢复后会重放该批次。这是当前明确的至少一次后端调用语义；
尚未通过请求缓存或外部幂等键消除潜在重复调用和费用。

## 推迟

本增量不实现真实模型或 Provider 进程、网络和凭据隔离、超时、异步取消、多进程调度、请求
缓存、翻译记忆、审计事件、用量和费用、预算审批、CLI/GUI、玩家工作区、自动渲染、导出或
启动。它也不把同步 Python 协议描述成能够约束不可信后端进程；真实后端必须在后续里程碑建立
独立的进程和权限边界。

## 结果

GalTrans 现在可以用测试内确定性后端从持久化任务安全执行一个批次，在重开数据库后继续，
并将失败、暂停和中断恢复作为应用自有状态保存。模型或替身仍无法直接接触游戏文件，验证通过
的提案仍不会自动进入渲染、导出或启动。

代价是崩溃重放可能再次调用后端，且同步调用无法在进程内强制超时或取消。缓存、费用去重和
受控 Provider 进程因此是后续明确工作，而不是本里程碑暗含的能力。
