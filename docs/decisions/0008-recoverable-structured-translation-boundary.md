# 0008：由 GalTrans 拥有可恢复的结构化翻译任务边界

- 状态：已接受
- 日期：2026-08-20

## 背景

V0.2 已经能把 Ren'Py 源脚本提取成统一文本段，并将经过检查的目标文本渲染、导出和验证；但
它还没有定义模型或确定性替身能够接收什么、必须返回什么，以及任务在暂停、失败或进程中断后
如何恢复。若先接入真实模型、缓存或 Agent Harness，外部会话很容易成为事实来源，旧来源结果
也可能越过当前的渲染与导出校验。

现有文本段已经具有不依赖绝对路径的稳定 `seg_` ID、IR schema 版本、来源文件 SHA-256 和
受保护标记。新边界应复用这些事实，而不是再发明一套引擎解析或让后端读取游戏文件。

## 决定

### 身份和筛选输入

GalTrans 继续使用提取器生成的 `seg_` ID。翻译任务 ID 对以下规范 JSON 计算 SHA-256 摘要：

- 翻译任务 schema 版本；
- 源语言、目标语言和批大小；
- 按调用方确定顺序排列的文本段请求，包括段 ID、IR schema、引擎、来源 SHA-256、类型、
  场景、说话人、原文和受保护标记。

批次 ID 再对任务 ID、批次序号和该批次的有序段 ID 计算摘要。摘要使用 24 个十六进制字符，
分别以 `task_` 和 `batch_` 开头。同一来源快照、顺序、语言和批策略会得到相同 ID；其中任一项
变化都会建立新任务，不能误接旧检查点或旧提案。

后端只接收 `TranslationBatch`。其中不含来源文件路径、行号、编码、项目根目录、SDK 或导出
路径；只保留翻译所需的结构化文本、有限场景与说话人上下文、来源摘要和标记记录。

### 提案 schema 和确定性验证

翻译提案 schema 版本从 1 开始，采用关闭式字段集合。每条提案必须回显：

- 提案 schema、任务、批次和文本段 ID；
- 来源 IR schema 和来源文件 SHA-256；
- 目标语言和来源受保护标记；
- 目标文本。

缺少字段、额外字段、错误类型、未知枚举或不支持版本都会失败关闭。核心验证任务、批次、段、
IR schema、来源哈希、目标语言和回显标记；之后必须由引擎适配器重新扫描目标文本的受保护标记。
当前 Ren'Py 适配器复用现有确定性扫描器，要求标记的种类、值和顺序与来源完全一致。只有通过
两层检查的结果才成为带内容摘要的 `ValidatedTranslation`，它仍是待后续处理的提案，不获得
渲染、导出、写文件、SDK 或启动权限。

### 状态和重复执行

任务状态为 `pending`、`running`、`paused`、`failed`、`completed`；批次状态为 `pending`、
`running`、`failed`、`completed`。GalTrans 检查点记录每批尝试次数、已验证提案 ID 和最后错误。

- 开始或重试批次时增加尝试次数；失败不会丢失已经完成的其他批次。
- 暂停或进程中断恢复会把尚未确认完成的 `running` 批退回 `pending`，允许安全重放。
- 从 `failed` 恢复会把失败批退回 `pending`，但保留尝试次数和最后错误供审计。
- 已完成批次收到相同的提案 ID 时幂等返回；收到不同结果时拒绝冲突重放。
- 只有一个批次的全部文本段都有已验证提案，才能将该批标记完成；只有全部批完成，任务才完成。

任务规范和检查点都提供严格的字典序列化与反序列化。本增量证明状态可以被持久化和重建，但
不把“可序列化”描述成已经实现崩溃安全的磁盘存储。

### 存储、缓存、审计和费用所有权

GalTrans 的 `pipeline` 拥有状态转移，未来 `storage` 层负责以原子事务保存任务规范、检查点、
提案正文、缓存索引、审计事件以及后端报告的用量和费用。后端会话 ID、缓存 ID 和用量报告都只是
可丢弃的外部引用或输入，不能代替本地状态，也不能自行把批次标记完成。

本增量不决定 SQLite 表结构、缓存淘汰、价格表、币种换算或预算审批 schema；这些需要与真实
提供方边界一起设计。文件级来源哈希目前会保守地使同文件中的旧任务全部失效，暂不增加更细的
缓存兼容规则。

### CI 替身

核心只定义接收 `TranslationBatch`、返回结构化提案的窄 `TranslationBackend` 协议。CI 中的
替身由测试代码根据批次内容同步产生固定提案，然后走与未来真实后端完全相同的 schema、来源、
标记和状态检查。测试不需要模型、网络、凭据、Ren'Py SDK 或图形桌面。

## 推迟

本决策不实现真实模型调用、Provider 或 Agent Harness 子进程、外部会话恢复、SQLite、缓存、
费用计算、角色卡、术语表、CLI、玩家 GUI、翻译输入界面、自动渲染/导出/启动或新引擎。也不
声明 Python 协议本身能够限制恶意后端进程的文件权限；真实后端的进程、网络、凭据和审批隔离
必须在后续小里程碑单独建立并测试。

## 结果

V0.3 后续实现可以替换模型提供方或使用完全确定性的 CI 替身，而不会改变任务身份、提案验证或
恢复语义。旧来源、损坏标记、未知 schema 和冲突重放会在到达 Ren'Py 渲染器之前被拒绝。

代价是批大小、顺序或文件内任何字节变化都会使任务和批次 ID 变化，可能降低早期缓存命中率；
在持久化与缓存兼容性有实际证据前，这个保守失效策略比猜测复用更安全。
