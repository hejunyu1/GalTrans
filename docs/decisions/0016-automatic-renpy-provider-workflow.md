# 0016：用首个受限 HTTP Provider 连接自动 Ren'Py 纵向流程

- 状态：已接受
- 日期：2026-08-25

## 背景

V0.3 已分别建立可恢复任务、SQLite 状态、Provider 回执、已验证结果缓存、质量报告和 Ren'Py
内存导出准备，但普通使用者仍须由代码手工组合这些边界。产品方向调整为先交付无人逐条审阅、
兼容范围明确受限的自动版本，再增加 GUI、可选审阅和高级质量能力。

要形成第一个真实纵向流程，GalTrans 必须接入网络模型、提供一个应用级入口，并能自动发布通过
验证的独立输出。同时不能让 Provider 获得游戏文件能力，也不能因同步网络结果不确定而盲目
重试或覆盖原游戏。

## 决定

### OpenAI 兼容同步 HTTP 适配器

第一版 Provider 使用用户明确配置的 Chat Completions endpoint、模型名和 API key。实现只依赖
Python 标准库。远程 endpoint 必须使用 HTTPS；HTTP 只允许本机回环测试。客户端拒绝 HTTP
重定向，把响应限制为 4 MiB，并使用系统默认 TLS 证书验证，不提供关闭验证的选项。

API key 只从环境变量进入进程内存和 `Authorization` 请求头，不作为 CLI 参数，不保存到 SQLite、
backend identity、错误信息或输出。命令创建 Provider 后会在执行 SDK 和应用流程期间临时从进程
环境移除密钥变量，结束时恢复，避免 Ren'Py 子进程继承凭据。backend identity 摘要 endpoint、
模型、固定提示版本和响应模式，使缓存不会因更换密钥失效，也不会泄漏密钥。

Provider 只接收已有的筛选 `TranslationBatch` 字段，不接收项目路径、SDK、工作区、输出位置、
文件内容读取工具或 Shell。系统提示把游戏文本明确视为不可信数据，只允许返回一个严格 JSON
对象。模型只需回显 `segment_id` 和 `target_text`；适配器用本地可信批次字段重建完整
`TranslationProposal`，再交给现有关闭式 schema 和引擎验证边界。

同步兼容协议不假定存在通用请求查询接口。400、401、403、404、405、413、415 和 422 被视为
明确失败；自动应用可以在用户配置的总次数内用同一幂等键受控重试。超时、重定向、429、5xx、
网络异常、超大响应或无法安全解析的成功响应保持 `unknown`，不自动重提。适配器的 `query`
明确返回无法消歧，而不是伪造服务端状态。

### 自动 source-only Ren'Py 应用流程

新增 `translate-renpy` 命令和应用服务，按以下顺序执行：

1. 在任何 Provider 调用前解析并检查输入项目、最小工作区和最终输出互不重叠，最终输出必须
   不存在；
2. 只读提取 `.rpy/.rpym`，在临时 source-only 副本上执行官方 SDK 交叉验证；
3. 在输入项目之外初始化或恢复 SQLite 任务，用稳定 backend identity 处理全部批次；
4. 在接受每条提案前验证 schema、来源、目标语言、受保护标记，并用对应 SDK 映射证明译文可以
   安全渲染；
5. 保存当前确定性质量报告，`low_confidence` 作为非阻塞警告继续流程；
6. 在最终输出同一父目录的临时树中写出翻译，使用完整临时 SDK lint 并独立 compile；
7. 只有验证通过才把临时翻译目录原子重命名为最终新目录，失败则清理半成品并保留可恢复任务。

自动流程不要求人工批准。这个决定只改变应用策略，不降低结构、来源、标记、路径、输出和 SDK
验证；`low_confidence` 继续如实持久化和报告，但不被解释为导出许可或质量保证。

## 推迟

本增量不实现 GUI、Windows 安装包、自动 SDK 下载、自动启动、费用统计、翻译记忆、审计、角色
卡、术语表、自动语义审校或低置信度二次翻译。它不支持 `.rpa/.rpyc`、加密或受保护游戏，也不
保证任意标称“OpenAI 兼容”的商业服务都与本机受控协议测试一致。

真实 endpoint、模型、凭据、数据发送和可能费用仍由用户选择。仓库测试不持有真实密钥，也不
产生商业服务调用费用。

## 结果

GalTrans 第一次拥有可以从 source-only Ren'Py 输入自动走到经过 lint/compile 验证的新翻译目录
的单一入口。原项目保持只读，Provider 仍没有文件或导出能力，验证失败不会发布半成品；已完成
的翻译结果可以在重新运行时从 SQLite 恢复。

代价是无人审阅输出可能包含错译、原文残留、术语和文风问题；首个同步协议在网络结果不确定时
必须停止，不能保证完全无人干预地从所有故障恢复。GUI 和普通成品游戏兼容仍是后续玩家 MVP 的
主要缺口。
