# 0013：用完整来源证据准备已完成 Ren'Py 提案

- 状态：已接受
- 日期：2026-08-24

## 背景

ADR 0008 至 0012 已经让 GalTrans 能筛选翻译输入、验证并持久化提案、恢复任务，以及消歧未来
Provider 的在途请求。V0.2 也已有保留官方语句结构的 Ren'Py 渲染器和只写全新目录的导出器，
但两侧尚无显式桥接。调用方若只按文本段 ID 把数据库提案交给渲染器，可能忽略未完成检查点、
冲突提案、已变化的来源快照或不属于同一 SDK 交叉验证结果的模板映射。

翻译任务有意不把来源路径和行号发送给 Provider，因此仅凭筛选任务无法证明一个官方模板映射
仍属于同一原始来源。桥接必须重新组合应用持有的确定性证据，而不是扩大 Provider 输入 schema。

## 决定

### 纯内存准备接口

Ren'Py 适配器提供 `prepare_renpy_translation_files`。调用方必须显式提供：

- 建立任务时使用的有序原始 `TextSegment`；
- `TranslationTask` 与当前 `TranslationTaskCheckpoint`；
- 与完成检查点对应的完整 `TranslationProposal` 集合，通常从应用存储恢复；
- 官方 SDK 交叉验证产生的 `RenpyTemplateMapping` 集合。

该接口只返回现有导出器的 `RenderedRenpyFile`，不接收输出目录，不调用 SDK、Shell 或启动器，
也不读取或写入游戏文件。

### 任务、检查点与提案证据

适配器先用原始文本段、任务语言和批策略重新建立任务；结果必须与调用方任务完全相同。检查点
必须通过关闭式反序列化，并且任务及全部批次均为 `completed`。

每条提案再次经过当前 Ren'Py 适配器验证，包括任务、批次、段、IR schema、来源 SHA-256、目标
语言和受保护标记。提案必须完整且唯一覆盖任务；按任务批次和段顺序计算的提案摘要必须与完成
检查点逐项一致。数据库记录或调用方参数不能用另一个合法但未被该检查点接受的译文替换它。

### SDK 映射证据与渲染

SDK 映射必须完整且唯一覆盖任务文本段。每个映射的段 ID、规范化来源路径、行号、文本类型、
原文和受保护标记都必须与对应原始 `TextSegment` 一致。现有渲染器随后继续检查官方原语句的
唯一字符串范围、目标引号安全和标记顺序；现有组装器继续检查语言、模板路径、文本段 ID 和官方
翻译 ID 冲突。

输出仍停留在内存。真正发布时，调用方必须另行显式选择全新且不与输入重叠的目录，并经过现有
写出和后续 SDK 验证边界；本决策不自动执行这些步骤。

## 推迟

本增量不增加任务或提案 schema 字段，不修改 SQLite，不实现玩家工作区、审阅批准、CLI、GUI、
磁盘发布、SDK 调用、启动、真实 Provider、网络、凭据、审计、费用、翻译记忆、质量评分或新
引擎。它也不持久化渲染文件；需要重新准备时必须重新提供并验证全部证据。

## 结果

GalTrans 现在有一条从“已完成检查点接受、仍需导出前复核的结构化提案”到“现有 Ren'Py 导出器
可接收的内存文件”的明确确定性路径。来源快照、检查点接受事实或 SDK 映射任一不一致都会在
文件写入前停止，模型或替身仍不能接触游戏文件、SDK、输出目录或启动能力。

代价是调用方必须保留原始提取记录与 SDK 交叉验证映射，并在每次准备时重新提供它们。玩家批准、
工作区生命周期和磁盘发布仍是后续应用层里程碑，不能把这个内存桥接描述成自动导出。
