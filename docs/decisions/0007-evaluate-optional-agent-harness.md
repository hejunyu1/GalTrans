# 0007：评估可选 Agent Harness，不把它设为确定性核心依赖

- 状态：提议中
- 日期：2026-08-20

## 背景

V0.3 需要模型服务抽象、结构化翻译提案、上下文、进度事件、暂停恢复、费用限制和审计记录。
其中长期上下文、工具调用、流式进度、失败处理和人工审批与 Agent Harness 的职责有重叠。

OpenAI 在 2026-08-19 发布了开源 Codex Harness 的平台说明。官方资料说明，Harness 可以管理
会话状态、工具调用、沙箱与审批，并通过 app-server 暴露线程、轮次和事件协议；应用仍然拥有
界面、业务规则、工具和结果记录。开源的是 Harness 与集成层，模型访问和托管服务仍然分离：

- [Codex as a platform: build on the open agent harness](https://developers.openai.com/blog/codex-as-a-platform)
- [Codex app-server 文档](https://learn.chatgpt.com/docs/app-server)
- [Codex SDK 文档](https://learn.chatgpt.com/docs/codex-sdk)

官方 Codex SDK 当前是需要 Node.js 18+ 的 TypeScript 库，与 GalTrans 的 Windows、Python 3.13
和标准库优先基础不直接吻合。app-server 也可作为本地子进程通过 `stdio` 交换 JSONL/JSON-RPC
消息，理论上可以由 Python 标准库客户端隔离接入；但部分动态工具和非 `stdio` 传输仍标为实验
能力，不能未经验证进入产品关键路径。

## 提议

先由 GalTrans 定义并拥有以下稳定边界，再评估任何 Harness：

1. 统一文本段和项目内上下文输入；
2. 带来源 ID、schema 版本和受保护标记的翻译提案；
3. 可恢复任务、缓存、费用上限、审批和审计状态；
4. 确定性 QA、Ren'Py 渲染、独立导出和启动验证。

Harness 只能位于上述边界内部，作为可替换 `AgentBackend` 的一种实现。直接模型调用和本地模型
必须可以实现同一应用自有接口，不能要求 GalTrans 用户必须使用 Codex 或单一模型提供方。

在 V0.3 基础接口稳定后，可以进行一个不进入正式产品路径的隔离原型：

- 只使用仓库内自制 Ren'Py 样例和结构化文本段；
- 优先从 Python 以本地 `stdio` 启动 app-server，不依赖实验性 WebSocket；
- Agent 只可读取 GalTrans 提供的文本批次、角色、术语和场景上下文；
- Agent 只可提交结构化翻译、术语和审校提案；
- 禁止通用 Shell、任意文件读取或写入、Ren'Py SDK、导出发布和网络搜索工具；
- 不把输入游戏目录、安装 SDK 或独立导出目录传给 Agent 进程；
- 将游戏文本作为不可信数据，加入伪装成系统指令的自制样例验证提示注入不会扩大权限；
- 所有提案返回后仍经过 GalTrans 的 schema、来源、标记和哈希验证。

正式集成前必须满足：

1. Windows 上可以有界启动、暂停、中断和结束进程，不留下孤儿进程；
2. CI 无 Codex、凭据、网络或模型时，可以用受控协议替身覆盖成功、失败、超时和未知事件；
3. 协议版本、未知字段和不兼容变更可以失败关闭并给出清晰诊断；
4. 玩家可以在调用前看到模型、联网、发送内容、预计费用和审批要求；
5. GalTrans 本地状态可以在外部会话丢失后恢复或安全重建任务；
6. 代表性自制翻译任务上的质量、延迟、费用和恢复能力优于或至少不劣于更简单的直接模型调用；
7. 安装体积、认证、更新和 Windows 打包成本不会破坏普通玩家的使用目标。

出现以下任一情况时放弃正式集成，继续使用更简单的提供方与确定性流水线：

- 无法可靠关闭通用文件、Shell 或其他与汉化无关的能力；
- 必须依赖不稳定实验协议才能提供最小工具集；
- 外部会话成为唯一任务状态或无法独立审计；
- 强制绑定单一模型、账户或无法向玩家解释的数据传输；
- 打包、认证、升级或资源开销明显高于所节省的编排代码；
- 代表性任务没有可测量收益。

## 影响

这项提议允许 GalTrans 借用成熟 Harness 的会话、进度、审批和工具循环，同时保持模型可替换性
和现有确定性安全边界。它也明确引入了新的协议、子进程、认证、供应商绑定和提示注入风险，
因此不能仅因组件开源就直接采用。

在原型完成并形成新的“已接受”ADR 之前，当前实现仍然没有 Agent Harness、模型调用或新增外部
依赖；本文件只记录评估方法和采用门槛。
