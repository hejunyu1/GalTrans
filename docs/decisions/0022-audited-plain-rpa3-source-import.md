# 0022：只把官方普通 RPA-3.0 中的源脚本导入可审计快照

- 状态：已接受
- 日期：2026-08-27

## 背景

V0.4.3 已能把标准 Ren'Py 成品识别为 `packaged_requires_import`，但该状态仍不能安全进入现有
source-only 自动流程。直接把所有 `.rpa` 当作可展开归档会混淆官方普通格式、自定义 loader、
混淆、加密和损坏输入；直接处理 `.rpyc/.rpymc` 又等于新增反编译边界，与当前产品非目标冲突。

[Ren'Py 官方构建文档](https://www.renpy.org/doc/html/build.html#archives)把 RPA 描述为简单归档，并
提醒其主要作用只是阻止随手复制。当前[官方归档器](https://github.com/renpy/renpy/blob/master/launcher/game/archiver.rpy)
写出 `RPA-3.0` 头、原始文件字节和 zlib 压缩 pickle 索引；
[官方加载器](https://github.com/renpy/renpy/blob/master/renpy/loader.py)从头部读取索引偏移与 XOR 键，
再按索引范围读取文件。这个公开、确定的普通子集足以建立第一个导入边界，但 pickle、路径、范围、
资源规模和输入变化都必须视为不可信。

## 决定

新增 `adapters.renpy.packaged_import` 内部接口。调用方必须传入关闭式
`USER_CONFIRMED_LOCAL_PROCESSING` 断言，输入必须重新获得 v1 兼容性报告的
`packaged_requires_import` 状态，输出必须是原游戏外尚不存在的新目录。授权断言只证明用户在
界面或上层流程中做了确认；GalTrans 不声称能自动判断版权许可、合同、DRM 或作者意图。

当前格式白名单只有严格 `RPA-3.0`：

- 头部必须直接包含 16 位十六进制索引偏移和 8 位十六进制 XOR 元数据键；未知、自定义或旧格式
  不尝试猜测；
- zlib 压缩流必须完整、无尾随数据，并同时受压缩与解压大小限制；
- pickle 使用受限 Unpickler；只允许内建容器，以及把 `renpy.python` 或 `renpy.revertable` 下的
  `RevertableDict`/`RevertableList` 安全映射为内建 `dict`/`list`，拒绝其他全局类型和持久化引用；
- 索引根必须是字典，每个条目必须是一个空前缀的单段整数范围，且完全位于索引前的数据区；
- 路径必须是 NFC 正斜杠相对路径，不含空段、`.`、`..`、反斜杠、控制符或冒号；要写出的源码
  还必须避开 Windows 保留名、非法字符、结尾点/空格、重复 `game` 前缀和大小写折叠冲突。

只把非 `tl` 的 `.rpy/.rpym` 作为源码候选。读取后必须通过现有保守编码识别，发布时保持原始
字节不变。`.rpyc/.rpymc` 与 `tl` 脚本只记录在忽略清单中，不按条目读取或解释正文、不反编译也
不复制；图片、音频、字体和其他资源不进入输出。为了形成归档 SHA-256，输入会在固定字节上限内
顺序读取一次整包，但不会据此展开非源码条目。至少有一个源码条目才能成功，因此只有编译脚本的
常见成品仍然明确不支持。

默认上限固定为 128 个归档、单个归档 8 GiB、全部归档 32 GiB、每个压缩或解压索引 32 MiB、
每个归档 50,000 项、单个源码 16 MiB、全部源码 128 MiB。公开参数只能进一步收紧这些限制，
不能关闭或放大当前支持矩阵。

输出先写入目标同一父目录的临时树，随后重新检查每个归档仍是相同普通文件，且文件身份、大小和
修改时间未变，最后原子重命名。任何失败都会清理临时树。`galtrans-import.json` v1 关闭式清单
记录授权断言、来源项目、稳定导入 ID、归档大小与 SHA-256、解压索引 SHA-256、条目计数，以及
逐源码的归档路径、索引名、偏移、大小、编码和 SHA-256。该清单让后续流程可以复核“从哪个输入
的哪个原始范围得到哪些字节”，但不会授予翻译、SDK、Provider、导出或启动权限。

## 授权与安全测试矩阵

| 输入 | 授权断言 | 结果 |
|---|---|---|
| 官方普通 RPA-3.0，含单段 `.rpy/.rpym` | 已确认 | 生成全新源码快照与清单 |
| 同上 | 缺失、字符串伪造或未知值 | 读取归档前拒绝 |
| 普通 RPA-3.0，仅含 `.rpyc/.rpymc` | 已确认 | 拒绝，不反编译 |
| 未知/自定义头部、危险 pickle、尾随数据、多段或前缀记录 | 已确认 | 写入前拒绝 |
| 路径穿越、Windows 冲突、范围或数量/大小超限 | 已确认 | 写入前拒绝 |
| 输出已存在、与输入重叠或归档在导入期间变化 | 已确认 | 拒绝并清理暂存树 |

测试只构造仓库测试代码生成的普通 RPA 字节与恶意索引，不包含或下载第三方游戏内容；成功与失败
路径都比较原输入文件 SHA-256 和修改时间。

## 推迟

本增量不接 Tauri、Tkinter 或 CLI，不自动调用导入、翻译、SDK、Provider、导出或启动；不复制
完整游戏、运行时或资源，也不生成可启动副本。不支持 RPA-1.0/2.0、未知后续版本、自定义 loader、
多段兼容记录、加密、混淆、DRM、RPYc 反编译或仅凭扩展名推断“未受保护”。如未来扩大矩阵，必须
以新的明确格式证据、自制/授权测试和独立决定逐项加入，不能放宽本边界的失败关闭规则。

## 结果

GalTrans 第一次能把一个非常窄、公开、非加密的标准成品子集转换成输入外的 source-only 候选
快照，同时保留原游戏、原始字节来源和完整哈希审计链。代价是绝大多数只发布编译脚本的成品仍然
不能处理，桌面状态仍会阻止继续；V0.4.4 建立的是后续玩家导入流程可复用的安全地基，不是成品
兼容已经完成。
