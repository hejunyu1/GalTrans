# GalTrans 开发路线

长期产品方向见 [`vision.md`](vision.md)，系统边界见 [`architecture.md`](architecture.md)。

路线图的最终产品结果是：普通 Windows 玩家选择自己合法持有且明确受支持的生肉游戏后，
无需接触 Python、命令行或游戏脚本，即可生成、启动并继续修正一个独立个人汉化副本。当前
版本仍只支持 source-only Ren'Py 项目，下面的后续里程碑会逐步补齐玩家流程。

## 已完成：V0.1 基础骨架

- [x] 隔离的 Python 3.13 运行环境
- [x] 只读项目扫描
- [x] 常见日中脚本编码检测
- [x] 文件哈希和基础元数据
- [x] 命令行入口
- [x] 不修改原文件的回归测试

## 已完成：Ren'Py 文本提取基础

- [x] 识别角色定义、台词、旁白和菜单选项
- [x] 为文本生成稳定 ID 和来源行号
- [x] 保护 `[variable]`、`{tag}` 和转义内容
- [x] 输出统一的 JSONL 中间格式
- [x] 验证“提取后不改变脚本”

完成条件：自制样例中的角色台词、旁白和菜单选项均可稳定提取；变量与文本标签被标记；
JSONL 可重复生成；输入文件哈希不变；测试全部通过。

## 已完成：V0.2 Ren'Py 可运行闭环

- [x] 验证现有 Ren'Py 8.5.3 SDK 的真实路径和版本
- [x] 在 source-only 临时副本上调用官方翻译生成与 lint
- [x] 交叉检查 GalTrans 与官方模板的对话、旁白和菜单数量
- [x] 用来源位置、类型和原文逐条匹配官方模板，并保留官方翻译 ID
- [x] 保证 SDK 缓存、存档、日志和编译产物不进入输入项目
- [x] 设计并实现纯内存生成 Ren'Py 官方翻译片段的接口
- [x] 将片段组装并写入不覆盖原文件的独立中文翻译目录
- [x] 在完整可写的临时 SDK 与 source-only 项目副本上 lint 并独立编译已导出目录
- [x] 启动和基础显示验证

当前小里程碑的逐条交叉检查只覆盖仓库内自制样例中的简单单语句台词、旁白和菜单，不代表
完整语法等价。导出后端只接收已经渲染的片段，尚未提供译文输入命令，也不保证片段覆盖全部
源文本。复杂官方模板块会被警告并跳过；当前 compile 和启动验证只覆盖仓库内自制 source-only
样例和独立导出目录，不代表真实游戏兼容性。基础显示证据只确认目标语言进程出现稳定的非零
窗口，不验证具体像素、译文、字体、溢出或交互路线。

## 后续

### 下一阶段 V0.3：翻译工作流

#### 已完成的小里程碑：可恢复的结构化翻译任务边界

- [x] 沿用稳定文本段 ID，并为来源快照、语言和批策略生成稳定任务与批次 ID
- [x] 定义只包含筛选文本和有限上下文的后端批次
- [x] 定义关闭式、版本化的结构化翻译提案 schema
- [x] 核对任务、批次、文本段、IR schema、来源 SHA-256 和目标语言
- [x] 由 Ren'Py 适配器重新扫描并精确验证译文受保护标记
- [x] 定义可序列化的暂停、恢复、失败、重试和幂等重放状态
- [x] 在 CI 中用测试内确定性后端替身覆盖该边界

这个任务边界本身不负责磁盘持久化；下面的 SQLite 小里程碑补上了提案正文和检查点引用的原子
保存。当前仍没有翻译命令，提案不会自动进入渲染或导出。

#### 已完成的小里程碑：SQLite 原子任务状态

- [x] 只在输入项目之外创建带明确 application ID 和 schema 版本的 SQLite 数据库
- [x] 原子保存并重开恢复任务规范与检查点，重复初始化不重置进度
- [x] 用旧检查点比较并交换，拒绝过期执行覆盖较新状态
- [x] 在同一事务保存经过引擎验证的提案正文与完成检查点
- [x] 对无效、缺失、冲突或来源不一致的提案整体回滚
- [x] 保持输入项目不变，并完全使用标准库和确定性 CI 测试

这仍不是完整玩家断点续传：当前没有工作区管理或任务执行命令，缓存、审计、费用和后端会话也
尚未持久化。恢复出的结构化提案在进入渲染或导出前仍须再次经过当前引擎适配器验证。

#### 已完成的小里程碑：确定性单批次执行

- [x] 从 SQLite 检查点按任务顺序选择一个待处理批次，调用后端前原子记录运行状态
- [x] 只把筛选后的 `TranslationBatch` 交给后端，并用当前引擎适配器验证全部返回提案
- [x] 原子保存完成检查点和提案正文，重开数据库后从下一批继续
- [x] 将后端异常、提案缺失和验证失败保存为可恢复失败，不落任何提案正文
- [x] 显式持久化暂停、失败恢复和中断恢复，重试时保留并增加尝试次数
- [x] 已完成任务重复执行不调用后端，迟到或过期状态由 SQLite 比较交换拒绝

当前执行器是同步、内部 API，每次最多执行一个批次。它没有超时或异步取消；若进程在后端响应
进入下面的本地缓存前中断，恢复后仍可能重新调用后端。CI 只使用确定性替身，不需要模型、网络、
凭据、SDK 或图形桌面。

#### 已完成的小里程碑：稳定请求身份与已验证结果缓存

- [x] 用完整筛选批次和显式 backend identity 生成内容寻址的稳定 `request_` ID
- [x] 将 SQLite schema 提升为 v2，只缓存经过引擎验证的完整结构化提案集
- [x] 按 backend identity 隔离缓存，拒绝相同请求键对应不同结果
- [x] 缓存命中时重新验证 schema、任务、来源哈希、语言和受保护标记
- [x] 后端成功后先保存缓存再提交完成检查点，重开后可避免重复调用已落盘响应
- [x] 明确拒绝旧 v1 和未知数据库 schema，不静默修改现有文件

该缓存不解决所有费用重复：如果请求已经到达未来的模型服务，但响应在本地验证和缓存前丢失，
GalTrans 仍无法仅凭本地状态判断服务端是否执行。真实 Provider 边界必须提供幂等键、请求查询或
明确的模糊失败审批策略。当前不做跨任务翻译记忆、缓存淘汰或数据库迁移。

#### 已完成的小里程碑：Provider 请求回执与模糊失败恢复

- [x] 沿用稳定 `request_` ID 作为同一筛选批次和 backend identity 的 Provider 幂等键
- [x] 定义关闭式调用回执，区分在途、成功、确定失败和结果未知
- [x] 将 SQLite schema 提升为 v3，以比较交换持久化回执和受限 Provider 请求引用
- [x] 提交前先保存未知回执，重开后按同一幂等键查询在途或未知请求
- [x] 只允许确定失败在显式恢复后受控重试，未知结果不能自动重提
- [x] 成功回执中的提案仍经过当前引擎验证，不能直接进入渲染、导出或启动

该边界目前只由确定性 Provider 替身验证，不包含真实网络、凭据、超时、取消、价格或费用记录。
它不能保证未来任一服务实际支持多久的幂等键或查询历史；若查询仍不能证明结果，任务保持在途并
要求人工处理。SQLite v1/v2 和未知版本继续失败关闭，不提供尚无用户数据需求支撑的迁移。

#### V0.3 后续小里程碑

- 真实模型服务的进程、网络、超时、凭据和审批边界
- SQLite 翻译记忆、审计事件和用量/费用记录
- 角色卡、术语表和场景上下文
- 将已验证提案显式交给现有 Ren'Py 渲染和导出边界
- 确定性质量检查和低置信度列表
- 为后续玩家界面增加可持久化、可报告的进度事件
- 在应用自有 schema、状态和提供方接口稳定后，按
  [ADR 0007](decisions/0007-evaluate-optional-agent-harness.md) 评估可选 Agent Harness；不把原型
  变成 V0.3 的强制运行时依赖

完成条件：对仓库内授权样例，可以从已验证的文本段生成结构化翻译建议，暂停后恢复任务，
拒绝标记损坏或来源不匹配的结果，并在不修改输入项目的前提下把通过校验的译文交给现有导出
边界。此阶段可以仍由测试或内部命令驱动，不把玩家 GUI 描述为已经完成。若进行 Harness
原型，它还必须只使用仓库内自制样例，以受控替身覆盖 CI，不获得通用 Shell、任意文件访问或
导出权限；原型失败或被放弃不影响基础翻译工作流达到完成条件。

### V0.4：玩家审阅工作台

- 本地 API 与 Web UI
- 游戏目录选择、引擎识别、兼容性报告和独立工作区状态
- 原文、译文、上下文和问题并排审阅
- 批量接受、退回、重试和差异检查
- 一键安全导出和启动验证，失败时给出玩家可理解的恢复建议

完成条件：非程序员测试用户无需执行命令即可在仓库内授权样例上完成导入、翻译、审阅、导出
和启动验证；界面始终区分原游戏、工作区和汉化副本，并能明确展示尚未支持的输入。

### V0.5：成品游戏兼容与扩展能力

- 在不破解 DRM 或绕过加密的前提下识别并支持一批明确记录的成品游戏分发结构
- 第二个游戏引擎适配器
- 图片、字体和 UI 本地化实验
- 游戏内自动化验证
- Windows 安装与升级流程实验，隐藏 Python 和项目脚本细节

### V1.0：可发布的玩家个人汉化工具

- 普通 Windows 玩家无需 Python、命令行或脚本知识即可完成完整流程
- 选择受支持的生肉游戏后，自动建立独立工作区并保持原游戏目录只读
- 完整的兼容性检查、提取、翻译、审阅、质检、导出和启动闭环
- 生成可重复启动、可继续修正且与原游戏分离的个人汉化副本
- 可恢复任务、翻译记忆和审计日志
- 插件接口与版本兼容策略
- 对不支持、加密、受保护或需要猜测的输入，在写入前安全停止并解释原因

完成条件：至少对公开列明的受支持范围和授权测试项目，首次使用的普通 Windows 测试用户可
仅通过图形界面完成上述闭环；原游戏哈希保持不变，所有生成物均位于明确的独立目录，失败后
可以恢复或重新开始，输出通过相应引擎的确定性检查与基础启动验证。V1.0 不承诺支持所有视觉
小说，也不把 OCR/Hook 实时字幕或受保护游戏解包计入完成范围。
