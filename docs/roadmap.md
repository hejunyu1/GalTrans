# GalTrans 开发路线

长期产品方向见 [`vision.md`](vision.md)，系统边界见 [`architecture.md`](architecture.md)。

## 已完成：V0.1 基础骨架

- [x] 隔离的 Python 3.13 运行环境
- [x] 只读项目扫描
- [x] 常见日中脚本编码检测
- [x] 文件哈希和基础元数据
- [x] 命令行入口
- [x] 不修改原文件的回归测试

## 已完成：Ren'Py 文本提取基础

- [x] 识别角色定义、台词、旁白和菜单选项
- [x] 为文本生成稳定 ID 和来源行号
- [x] 保护 `[variable]`、`{tag}` 和转义内容
- [x] 输出统一的 JSONL 中间格式
- [x] 验证“提取后不改变脚本”

完成条件：自制样例中的角色台词、旁白和菜单选项均可稳定提取；变量与文本标签被标记；
JSONL 可重复生成；输入文件哈希不变；测试全部通过。

## 当前：V0.2 Ren'Py 可运行闭环

- [x] 验证现有 Ren'Py 8.5.3 SDK 的真实路径和版本
- [x] 在 source-only 临时副本上调用官方翻译生成与 lint
- [x] 交叉检查 GalTrans 与官方模板的对话、旁白和菜单数量
- [x] 用来源位置、类型和原文逐条匹配官方模板，并保留官方翻译 ID
- [x] 保证 SDK 缓存、存档、日志和编译产物不进入输入项目
- [ ] 设计并实现生成 Ren'Py 官方翻译块的接口
- [ ] 生成不覆盖原文件的中文翻译目录
- [ ] 在明确的可写副本上完成独立编译验证
- [ ] 启动和基础显示验证

当前小里程碑的逐条交叉检查只覆盖仓库内自制样例中的简单单语句台词、旁白和菜单，不代表
完整语法等价，也不会生成译文。复杂官方模板块会被警告并跳过；独立 `compile`、图形启动
和显示验证仍是 V0.2 后续工作。

## 后续

### V0.3：翻译工作流

- 模型服务抽象、请求缓存和断点续传
- 角色卡、术语表和场景上下文

- 确定性质量检查和低置信度列表

### V0.4：审阅工作台

- 本地 API 与 Web UI
- 原文、译文、上下文和问题并排审阅
- 批量接受、退回、重试和差异检查

### V0.5：扩展能力

- 第二个游戏引擎适配器
- 图片、字体和 UI 本地化实验
- 游戏内自动化验证

- 完整导入到导出闭环
- 可恢复任务、翻译记忆和审计日志
- 插件接口与版本兼容策略
- 授权项目的测试补丁构建
