# GalTrans 开发路线

长期产品方向见 [`vision.md`](vision.md)，系统边界见 [`architecture.md`](architecture.md)。

路线图的最终产品结果是：普通 Windows 玩家选择自己合法持有且明确受支持的生肉游戏后，
无需接触 Python、命令行或游戏脚本，即可生成、启动并继续修正一个独立个人汉化副本。当前
版本仍只支持 source-only Ren'Py 项目，下面的后续里程碑会逐步补齐玩家流程。

## 已完成：V0.1 基础骨架

- [x] 隔离的 Python 3.13 运行环境
- [x] 只读项目扫描
- [x] 常见日中脚本编码检测
- [x] 文件哈希和基础元数据
- [x] 命令行入口
- [x] 不修改原文件的回归测试

## 已完成：Ren'Py 文本提取基础

- [x] 识别角色定义、台词、旁白和菜单选项
- [x] 为文本生成稳定 ID 和来源行号
- [x] 保护 `[variable]`、`{tag}` 和转义内容
- [x] 输出统一的 JSONL 中间格式
- [x] 验证“提取后不改变脚本”

完成条件：自制样例中的角色台词、旁白和菜单选项均可稳定提取；变量与文本标签被标记；
JSONL 可重复生成；输入文件哈希不变；测试全部通过。

## 已完成：V0.2 Ren'Py 可运行闭环

- [x] 用来源位置、类型和原文逐条匹配官方模板，并保留官方翻译 ID
- [x] 保证 SDK 缓存、存档、日志和编译产物不进入输入项目
- [x] 设计并实现纯内存生成 Ren'Py 官方翻译片段的接口

- [x] 在完整可写的临时 SDK 与 source-only 项目副本上 lint 并独立编译已导出目录
- [x] 启动和基础显示验证

当前小里程碑的逐条交叉检查只覆盖仓库内自制样例中的简单单语句台词、旁白和菜单，不代表
完整语法等价。V0.2 导出后端只接收已经渲染的片段，当时尚未提供译文输入命令，也不保证片段
覆盖全部源文本。复杂官方模板块会被警告并跳过；当前 compile 和启动验证只覆盖仓库内自制 source-only
样例和独立导出目录，不代表真实游戏兼容性。基础显示证据只确认目标语言进程出现稳定的非零
窗口，不验证具体像素、译文、字体、溢出或交互路线。

## 后续

### 已完成：V0.3 翻译工作流核心

#### 已完成的小里程碑：可恢复的结构化翻译任务边界

- [x] 沿用稳定文本段 ID，并为来源快照、语言和批策略生成稳定任务与批次 ID
- [x] 定义只包含筛选文本和有限上下文的后端批次
- [x] 定义关闭式、版本化的结构化翻译提案 schema
- [x] 核对任务、批次、文本段、IR schema、来源 SHA-256 和目标语言
- [x] 由 Ren'Py 适配器重新扫描并精确验证译文受保护标记
- [x] 定义可序列化的暂停、恢复、失败、重试和幂等重放状态
- [x] 在 CI 中用测试内确定性后端替身覆盖该边界

这个任务边界本身不负责磁盘持久化；下面的 SQLite 小里程碑补上了提案正文和检查点引用的原子
保存。该边界自身仍不负责翻译命令，提案不会仅凭 schema 校验自动进入渲染或导出。

#### 已完成的小里程碑：SQLite 原子任务状态

- [x] 只在输入项目之外创建带明确 application ID 和 schema 版本的 SQLite 数据库
- [x] 原子保存并重开恢复任务规范与检查点，重复初始化不重置进度
- [x] 用旧检查点比较并交换，拒绝过期执行覆盖较新状态
- [x] 在同一事务保存经过引擎验证的提案正文与完成检查点
- [x] 对无效、缺失、冲突或来源不一致的提案整体回滚
- [x] 保持输入项目不变，并完全使用标准库和确定性 CI 测试

该 SQLite 增量本身还不是完整玩家断点续传：后续自动命令只增加了最小任务工作区，缓存、审计、
费用和通用后端会话仍未完整持久化。恢复出的结构化提案在进入渲染或导出前仍须再次经过当前
引擎适配器验证。

#### 已完成的小里程碑：确定性单批次执行

- [x] 从 SQLite 检查点按任务顺序选择一个待处理批次，调用后端前原子记录运行状态
- [x] 只把筛选后的 `TranslationBatch` 交给后端，并用当前引擎适配器验证全部返回提案
- [x] 原子保存完成检查点和提案正文，重开数据库后从下一批继续
- [x] 将后端异常、提案缺失和验证失败保存为可恢复失败，不落任何提案正文
- [x] 显式持久化暂停、失败恢复和中断恢复，重试时保留并增加尝试次数
- [x] 已完成任务重复执行不调用后端，迟到或过期状态由 SQLite 比较交换拒绝

当前执行器是同步、内部 API，每次最多执行一个批次。它没有超时或异步取消；若进程在后端响应
进入下面的本地缓存前中断，恢复后仍可能重新调用后端。CI 只使用确定性替身，不需要模型、网络、
凭据、SDK 或图形桌面。

#### 已完成的小里程碑：稳定请求身份与已验证结果缓存

- [x] 用完整筛选批次和显式 backend identity 生成内容寻址的稳定 `request_` ID
- [x] 将 SQLite schema 提升为 v2，只缓存经过引擎验证的完整结构化提案集
- [x] 按 backend identity 隔离缓存，拒绝相同请求键对应不同结果
- [x] 缓存命中时重新验证 schema、任务、来源哈希、语言和受保护标记
- [x] 后端成功后先保存缓存再提交完成检查点，重开后可避免重复调用已落盘响应
- [x] 明确拒绝旧 v1 和未知数据库 schema，不静默修改现有文件

该缓存不解决所有费用重复：如果请求已经到达未来的模型服务，但响应在本地验证和缓存前丢失，
GalTrans 仍无法仅凭本地状态判断服务端是否执行。真实 Provider 边界必须提供幂等键、请求查询或
明确的模糊失败审批策略。当前不做跨任务翻译记忆、缓存淘汰或数据库迁移。

#### 已完成的小里程碑：Provider 请求回执与模糊失败恢复

- [x] 沿用稳定 `request_` ID 作为同一筛选批次和 backend identity 的 Provider 幂等键
- [x] 定义关闭式调用回执，区分在途、成功、确定失败和结果未知
- [x] 将 SQLite schema 提升为 v3，以比较交换持久化回执和受限 Provider 请求引用
- [x] 提交前先保存未知回执，重开后按同一幂等键查询在途或未知请求
- [x] 只允许确定失败在显式恢复后受控重试，未知结果不能自动重提
- [x] 成功回执中的提案仍经过当前引擎验证，不能直接进入渲染、导出或启动

该回执边界最初只由确定性 Provider 替身验证；后续首个同步 HTTP 适配器增加了网络、凭据和超时
边界，但仍没有取消、价格或费用记录。
它不能保证未来任一服务实际支持多久的幂等键或查询历史；若查询仍不能证明结果，任务保持在途并
要求人工处理。SQLite v1/v2 和未知版本继续失败关闭，不提供尚无用户数据需求支撑的迁移。

#### 已完成的小里程碑：已完成 Ren'Py 提案的内存导出准备

- [x] 从原始 `TextSegment`、语言和批策略重建并核对翻译任务身份
- [x] 只接受全部批次完成的检查点，并逐批核对已接受提案摘要
- [x] 对恢复出的每条提案重新执行当前 Ren'Py 来源和受保护标记验证
- [x] 要求 SDK 映射完整且唯一覆盖任务，并核对来源路径、行号、类型、原文和标记
- [x] 调用现有 Ren'Py 渲染器与组装器，确定性返回内存 `RenderedRenpyFile`
- [x] 不调用 SDK、不写输出目录、不启动游戏，也不向 Provider 暴露文件或导出能力

这个桥接只解决“已接受提案如何安全到达现有确定性导出边界”，不等于玩家批准发布。调用方仍须
显式选择全新输出目录并调用现有写出边界；后续自动命令负责组合这些证据，但仍没有完整玩家
工作区管理、审阅状态或自动启动。

#### 已完成的小里程碑：首个确定性质量检查与低置信度结果边界

- [x] 接收完整的任务与已经过引擎校验的译文，核对任务、批次、来源、语言和提案摘要
- [x] 定义关闭式、版本化的质量报告、检查 ID、结构化问题代码和逐文本段结果
- [x] 按任务顺序稳定生成 `clear` 与 `low_confidence` 结果，并提供低置信度列表
- [x] 将 Unicode NFC 规范化后仍与原文完全相同的译文标记为需要复核
- [x] 拒绝缺失、重复、陈旧、身份冲突或内容摘要不一致的质量检查输入
- [x] 保持纯内存、标准库和确定性测试，不读取游戏、不修改 SQLite、也不触发导出

`low_confidence` 只表示当前结构化问题需要复核；`clear` 只表示首条规则未命中，不代表译文
正确、自然或高置信度。专名和无需翻译的文本可能合理地被列入复核，稍作改动的低质量译文也
可能不被发现。报告本身不承担人工审批或导出许可；下面的增量只持久化可重新计算的报告事实。

#### 已完成的小里程碑：SQLite 质量报告持久化与恢复

- [x] 将 SQLite schema 提升为 v4，为每个翻译任务保存一份规范质量报告
- [x] 只允许全部批次完成且提案正文已原子持久化的任务保存报告
- [x] 从检查点真正接受的提案重新执行当前引擎验证和确定性质量检查
- [x] 相同报告幂等保存，拒绝伪造 outcome、替换提案、冲突覆盖和损坏 JSON
- [x] 关闭并重开数据库后重新验证报告，未生成报告时明确返回 `None`
- [x] 保持输入项目不变，不接人工审批、Provider、网络、GUI、CLI 或导出能力

质量报告现在可以恢复，但人工批准、驳回、备注和问题豁免仍未定义，报告也不会授予导出权限。
SQLite v1 至 v3 和未知版本继续失败关闭；实现该存储增量时尚无 CLI，当前也没有长期用户数据库，
因此不增加未经真实数据与备份策略验证的迁移代码。

#### 已完成的小里程碑：首个全自动 source-only Ren'Py 纵向流程

- [x] 增加只接收筛选批次的 OpenAI 兼容 Chat Completions HTTPS Provider
- [x] API key 只从环境变量进入请求头，不进入参数、backend identity、SQLite 或结果
- [x] 在调用 Provider 前完成只读提取和官方 SDK 交叉验证
- [x] 自动恢复任务、处理全部批次，并对明确失败进行有上限的受控重试
- [x] 在接受提案前同时验证 schema、来源、受保护标记和 Ren'Py 可渲染性
- [x] 自动生成并持久化当前确定性质量报告，低置信度作为非阻塞警告
- [x] 在同盘临时目录写出并通过 SDK lint/compile 后，原子发布到全新输出目录
- [x] 提供 `translate-renpy` 命令，把 endpoint、模型、工作区和安全输出边界连接起来

这个纵向流程不要求逐条人工审阅，优先让普通玩家版本尽快形成可运行主干。代价是
`low_confidence`、错译、文风和术语问题可能进入输出；当前报告只如实提示，不代表语义质量保证。
同步 Chat Completions 兼容协议没有统一的请求查询保证，网络结果不确定时仍会安全停止，不盲目
重复产生费用。网络请求和结构协议已由本机 HTTP 服务测试，但尚未使用用户的真实商业服务、凭据
或费用验证。当前命令也不自动启动游戏。

#### 后续改进（不阻塞首个玩家 MVP）

- 更多真实 Provider 的差异适配、用量/费用记录和隐私提示
- SQLite 翻译记忆和审计事件
- 角色卡、术语表和场景上下文
- 更多确定性质量检查、自动纠错与独立语义审校边界
- 可选的人工复核状态，不作为默认自动流程的前置条件
- 为后续玩家界面增加可持久化、可报告的进度事件
- 在应用自有 schema、状态和提供方接口稳定后，按
  [ADR 0007](decisions/0007-evaluate-optional-agent-harness.md) 评估可选 Agent Harness；不把原型
  变成 V0.3 的强制运行时依赖

完成条件：对仓库内授权样例，可以从已验证的文本段生成结构化翻译建议，暂停后恢复任务，
拒绝标记损坏或来源不匹配的结果，并在不修改输入项目的前提下把通过校验的译文交给现有导出
边界。此阶段可以仍由测试或内部命令驱动，不把玩家 GUI 描述为已经完成。若进行 Harness
原型，它还必须只使用仓库内自制样例，以受控替身覆盖 CI，不获得通用 Shell、任意文件访问或
导出权限；原型失败或被放弃不影响基础翻译工作流达到完成条件。

### 进行中：V0.4 自动玩家工作台

#### 已完成的小里程碑：最小 Windows 自动汉化界面

- [x] 用 Python 标准库 Tkinter 提供 SDK、源项目、全新输出、Provider、模型和 API key 输入
- [x] 直接复用 V0.3 自动流程，不在界面层复制提取、翻译、校验或导出逻辑
- [x] 用后台线程运行耗时任务，主界面通过队列接收进度、成功和失败事件
- [x] 为自动流程定义稳定阶段进度：路径、提取、SDK、批次、质检、渲染、验证、发布和完成
- [x] API key 不进入命令行、环境、工作区或日志，开始后立即清空输入框并在错误中隐藏
- [x] 成功或失败都恢复输入与开始按钮；运行时不提供不安全的强制线程取消

这个界面已经让用户不必拼写翻译命令，但仍依赖仓库 Python 环境、Ren'Py SDK 和明确配置的
OpenAI 兼容服务。它不是 Windows 安装包，不支持普通 `.rpa/.rpyc` 成品游戏，不自动下载 SDK、
启动游戏或生成完整可独立游玩的游戏副本。真实商业 Provider 兼容性和费用仍未实机验证。

#### 已完成的小里程碑：现代 TypeScript + Tauri 玩家工作台

- [x] 用 React 和 TypeScript 重做三步配置、实时进度、结果、警告和错误界面
- [x] 用 Tauri 2 提供原生 Windows 窗口和文件夹选择，不给前端通用文件或 Shell 能力
- [x] 将 Tkinter 中的玩家应用服务抽成共享模块，两个界面不复制自动流程
- [x] 用关闭式 v1 JSON 请求和 JSONL 事件桥连接固定 Python 子进程，并限制消息大小
- [x] Rust 边界重新校验请求、阶段、计数、质量结果和终态，且同时只允许一个任务
- [x] API key 只通过子进程标准输入传递，不进入命令行、环境变量、SQLite 或日志
- [x] 保留 Tkinter 作为回退入口，并用真实 Windows 窗口验证布局、表单错误和文件夹选择器

这个小里程碑完成时，现代工作台已经能从仓库开发环境启动并调用相同的 source-only 自动流程，
但仍依赖仓库 `.venv`。后面的固定 sidecar 小里程碑已消除这项运行时依赖；正式安装器、自动更新
和签名仍未实现，因此当前仍是可试用开发版，而不是可直接安装的普通玩家成品。

#### 已完成的小里程碑：只读 Ren'Py 成品识别与兼容性报告

- [x] 接受游戏安装根目录或其 `game` 目录，确定性定位标准 Ren'Py 项目边界
- [x] 区分非翻译源脚本、编译脚本、RPA 归档和已有 `game/tl` 翻译文件
- [x] 报告根目录启动器、`renpy`/`lib` 运行时标记和有界读取的版本线索
- [x] 用关闭式 v1 状态区分当前可用、成品待导入、证据不确定和非 Ren'Py
- [x] 限制扫描深度与项目数，跳过链接和目录联接，扫描不完整时安全返回不确定
- [x] 用自制伪成品结构验证不读取归档内容，且检查前后所有输入哈希和修改时间不变

这个增量当时只提供 Python 内部兼容性接口；后续桌面接入见下方 V0.4.3 小里程碑。`source_ready` 仍只代表当前
source-only 流程可以继续；`packaged_requires_import` 只代表有足够证据识别标准成品结构，不代表
已经能提取或汉化其中内容。GalTrans 不读取 RPA 内容、不反编译 RPYc、不运行游戏，也不把扩展名
当成解密或授权证据。

#### 已完成的小里程碑：固定 Python 后端 Tauri sidecar

- [x] 用固定版本 PyInstaller 将桌面桥、GalTrans 模块、CPython 和所需标准库打包为单文件 Windows 后端
- [x] 按当前 Rust 目标三元组生成 Tauri `externalBin` 输入，并在复制前运行关闭式 JSONL 冒烟测试
- [x] Rust 只启动应用资源目录中的固定 `galtrans-backend.exe`，不再查找仓库、`.venv` 或源码
- [x] sidecar 不接收命令行参数，API key 仍只通过标准输入传递，并移除 Python/API key 环境变量
- [x] 保持前端只有目录选择和 `start_translation`；不增加通用 Shell、文件系统或 Provider 权限
- [x] 生成无安装器的 Tauri release 目录，忽略 sidecar 与构建产物，并在 Windows CI 重建验证

这个增量只消除了工作台运行时对仓库 Python 环境的依赖；从源码构建仍需要 Python 3.13、固定
PyInstaller、Node.js 和 Rust，实际翻译仍需要用户提供 Ren'Py SDK、endpoint、模型和 API key。
