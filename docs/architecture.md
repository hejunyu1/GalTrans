# GalTrans 架构

## 核心原则

```text
玩家选择的游戏目录（只读）
  ↓  引擎识别、兼容性检查与独立工作区
引擎适配器（确定性、只读提取）
  ↓
统一中间格式
  ↓  上下文与翻译流水线（结构化结果）
质量检查与人工审阅
  ↓  引擎适配器（受校验导出）
独立个人汉化副本 / 专业翻译资源
```

引擎格式处理和语言处理必须分离。翻译模块不读取或修改任意游戏脚本；它只接收统一文本段。
面向玩家的应用层负责把兼容性检查、独立工作区、翻译、审阅、导出和启动组织成可恢复流程，
但不能绕过适配器和校验边界直接操作游戏内容。

## 当前已实现

- 常见文本文件的只读项目扫描。
- UTF-8、UTF-16、CP932 和 GB18030 的保守检测。
- 文件哈希、编码、大小和行数元数据。
- CLI、标准库测试、自制 Ren'Py 样例和 GitHub 自动测试。
- Ren'Py 保守提取器：
  - 识别角色定义、角色台词、旁白和菜单选项。
  - 为文本记录文件、标签、行号、说话人和稳定 ID。
  - 标记 `[interpolation]`、`{text tags}` 和反斜杠转义。
  - 输出 JSONL 中间数据。
  - 对不确定语法发出警告，不猜测完整 Ren'Py 语义。
- Ren'Py SDK 交叉验证边界：
  - 从外层下载目录或明确的可执行文件定位唯一 SDK 根目录。
  - 用 `--version` 探测 SDK，在临时的 source-only 项目镜像上运行 `translate` 和 `lint`。
  - 读取官方模板中的来源位置、原文和翻译 ID，并与 GalTrans 文本段逐条匹配。
  - 对多语句等尚不明确的模板块发出警告，不把数量相同当作文本等价。
  - 将 SDK 产生的翻译目录、缓存、存档、日志和编译文件限制在临时目录。
  - 将非零退出码以及输出中的 Traceback、文件或权限错误都视为失败。
- Ren'Py 官方翻译片段渲染：
  - 从官方模板保留原语句、唯一字符串范围和翻译 ID，不重新猜测角色或语句结构。
  - 纯内存生成台词/旁白 `translate` 块或菜单 `old/new` 条目，不执行文件写入。
  - 渲染前验证来源记录、语言名、字符串边界以及受保护标记的精确顺序。
- Ren'Py 独立补丁目录写出：
  - 按官方模板文件分组片段，并为每个文件生成至多一个 `translate strings` 容器。
  - 使用 UTF-8 BOM 和 LF 写入 `game/tl/<language>`，与官方新模板编码行为兼容。
  - 输出根目录必须全新且不得与输入项目重叠；在同一父目录暂存后发布。
- Ren'Py 导出目录验证：
  - 要求 SDK、source-only 输入项目和独立导出根目录互不重叠，三个输入都只读。
  - 将完整 SDK 和项目源脚本复制到可写临时树，再把导出的 `game/tl/<language>` 合并进去。
  - 从临时 SDK 依次运行 `lint` 和独立 `compile`，并要求所有项目与翻译源脚本生成编译文件。
  - lint 产生的项目编译物会在 compile 前删除；缓存、存档、日志和 SDK 编译物随临时树清理。
- Ren'Py 启动与基础显示验证：
  - 复用完整临时 SDK、source-only 项目副本和独立导出合并边界，并通过环境固定目标语言。
  - 只允许从临时 SDK 执行 `run --savedir`，以稳定可见且客户区非零的进程窗口作为证据。
  - 临时退出脚本仅把窗口关闭改为无确认正常退出；保留路径冲突时拒绝启动。
  - 显示前退出、超时、错误文件或致命输出均失败；显示后按正常关闭、terminate、kill 升级。
  - Windows Job Object 终止并确认进程树清空；日志、用户数据和系统临时目录都重定向到临时根。
- 可恢复的结构化翻译任务边界：
  - 从统一文本段、语言和批策略生成内容寻址的稳定任务与批次 ID。
  - 后端批次不含游戏路径、来源行号、编码、SDK 或导出位置。
  - 关闭式提案 schema 回显任务、批次、段、IR schema、来源 SHA-256、目标语言和受保护标记。
  - 核心核对来源快照，Ren'Py 适配器重新扫描目标标记；通过后仍只产生待处理提案。
  - 可序列化检查点表达暂停、恢复、失败、重试和已完成批次的幂等重放。
  - `TranslationBackend` 仅是接收筛选批次并返回结构化提案的窄协议；CI 使用测试内确定性替身。
- SQLite 翻译状态存储：
  - 数据库必须位于只读输入项目之外，并拒绝符号链接、普通 SQLite 文件和未知 schema。
  - 规范任务与检查点重开后严格反序列化，相同任务重复初始化不会重置进度。
  - 使用 `BEGIN IMMEDIATE` 和旧检查点比较并交换，防止过期执行覆盖较新状态。
  - 已验证提案正文和检查点引用在同一事务提交；来源或标记检查失败时整体回滚。
  - 恢复出的提案仍须由当前引擎适配器重新验证，不能直接进入渲染或导出。
- 确定性单批次翻译执行器：
  - 每次只从持久化检查点选择第一个待处理批次，调用前先原子记录 `running` 和尝试次数。
  - 后端只接收已有的筛选 `TranslationBatch`；返回值经过当前引擎验证后才与完成检查点原子保存。
  - 后端异常、提案缺失或验证失败会保存 `failed`，不保存任何提案正文。
  - 暂停、失败和中断任务必须显式恢复；重开数据库后从未完成批次继续，完成任务幂等返回。
  - 比较交换拒绝暂停后的迟到结果或其他执行者的过期提交，不允许后端自行推进任务状态。

## 当前限制与下一阶段

现有提取器不是完整 Ren'Py 语法解析器。当前 SDK 边界可以逐条交叉验证简单的单语句台词、
旁白和菜单，但会拒绝猜测多语句等复杂官方模板块。纯内存渲染器可以生成单条官方格式片段，
导出后端可以把调用方提供的片段写入全新补丁目录，并能在完整可写的 SDK 与 source-only 项目
临时副本中 lint、独立编译和基础启动该目录，但尚未提供译文输入命令，也不验证片段是否覆盖
全部源文本。基础显示只证明目标语言启动出现了真实非零窗口，不检查像素、实际译文、字体、
文本溢出或交互路线。

结构化翻译任务、检查点和已接受提案现在可以在输入项目之外原子保存并重开恢复，内部执行器能
通过确定性替身每次处理一个批次，但仍没有请求缓存、翻译记忆、审计事件、费用核算、真实后端
进程、玩家工作区管理或翻译命令。执行器和存储 API 尚未被 CLI 调用，通过提案验证和持久化也
不等于获准渲染或导出。

当前输入仍必须是带 `.rpy/.rpym` 源脚本的 Ren'Py 项目，不支持普通玩家通常拿到的所有成品
游戏，也没有玩家 GUI、自动模型翻译或一键生成可游玩副本。将这些能力写入产品方向不代表它们
已经实现；后续里程碑必须逐步缩小这一差距，并对无法处理的封装、加密或魔改格式返回明确的
不支持结果。

## 计划模块

| 模块 | 职责 |
|---|---|
| `adapters` | 引擎专属提取与导出 |
| `core` | 统一中间格式、任务状态和错误模型 |
| `providers` | 云端与本地模型统一接口 |
| `context` | 角色、术语、场景摘要和路线信息 |
| `pipeline` | 可恢复的翻译与审校工作流 |
| `qa` | 确定性检查和语义检查 |
| `storage` | SQLite、翻译记忆、缓存和审计记录 |
| `api` | 供本地玩家界面使用的受限接口 |
| `ui` | 游戏选择、兼容性提示、任务进度、译文审阅和副本启动 |

## Agent 编排边界（计划）

V0.3 首先定义模型提供方、结构化翻译提案、任务状态、缓存和恢复边界，不以任何特定 Agent
Harness 作为核心前提。在这些应用自有接口稳定后，可以按
[ADR 0007](decisions/0007-evaluate-optional-agent-harness.md) 对外部 Harness 做隔离原型。候选实现
包括 OpenAI 开源 Codex Harness 的本地 app-server `stdio` 协议，但当前没有采用决定，也没有
实现或运行时依赖。

计划中的调用关系是：

```text
玩家界面 / 确定性任务状态
  ↓
GalTrans pipeline
  ↓
可替换的 TranslationBackend
  ├─ 直接模型提供方
  ├─ 可选 Codex Harness 适配器
  └─ 可选本地模型适配器
  ↓
结构化翻译提案
  ↓
GalTrans 确定性校验与导出
```

无论采用哪一种编排实现，Harness 都不得成为项目事实来源，也不得绕过现有边界：

- Agent 只接收统一文本段、项目内上下文和经过筛选的翻译记忆，不接收任意文件系统访问。
- 不向 Agent 暴露通用 Shell、文件写入、Ren'Py SDK 启动或导出发布工具。
- 游戏文本始终作为不可信数据处理，其中类似指令的内容不能改变工具权限或系统规则。
- Agent 只能提交带来源 ID 的结构化翻译、术语或审校提案；所有提案必须重新验证来源哈希、
  受保护标记、结构版本和目标 schema。
- GalTrans 自己保存任务、费用、审批、缓存和审计状态；外部线程或会话 ID 只是可丢弃的后端
  引用，不能代替可恢复的本地状态。
- 模型访问、联网、可能费用和数据发送范围必须由玩家明确选择；开源 Harness 不等于免费或
  离线模型。

当前只实现了应用自有的 `TranslationBackend` 数据协议和确定性测试替身；没有提供方执行器、
Agent 子进程或外部会话。基础 SQLite 状态已经由 GalTrans 持有，但 Harness 原型仍须等待缓存、
用量和审批边界稳定，不创建运行时依赖。任务和提案边界见
[ADR 0008](decisions/0008-recoverable-structured-translation-boundary.md)，原子持久化见
[ADR 0009](decisions/0009-atomic-sqlite-translation-state.md)，单批次执行边界见
[ADR 0010](decisions/0010-deterministic-single-batch-execution.md)。

## 稳定 ID

文本段 ID 不依赖绝对路径，避免项目换电脑后全部变化。初版使用以下信息计算摘要：

- 项目内相对路径；
- Ren'Py 标签；
- 文本类型；
- 说话人；
- 原文；
- 同一标签内完全相同文本的出现序号。

因此单纯增加空行或移动行号不会改变 ID；原文、语义位置或重复顺序改变时会生成新 ID。

每条 JSONL 文本段还携带中间格式版本、源编码和源文件 SHA-256。虽然这些字段在同一文件的
多条文本中会重复，但每一条记录都能独立验证来源，也便于拆分任务和恢复失败批次。

## 写入边界

- 扫描与提取默认只读。
- 导出只能写入独立输出目录或明确指定的新文件。
- 当前 Ren'Py 目录导出要求整个输出根目录不存在，不提供覆盖模式。
- 未来写回前必须验证输入哈希、标记集合、编码和目标语法。
- 玩家选择的游戏安装目录始终视为只读输入；工作文件和最终汉化版本只能位于独立位置。
- 不为扩大兼容性而破解 DRM、绕过加密或猜测未知封装格式。

## Ren'Py SDK 调用边界

GalTrans 不在用户输入项目上直接运行 SDK。交叉验证只复制 `game` 下非 `tl` 目录中的
`.rpy/.rpym` 文件，SDK 可执行文件和其自带模块作为外部工具保持在原位置。当前允许的命令是：

```text
renpy.exe --version
renpy.exe <临时项目> translate <language> --savedir <临时存档目录>
renpy.exe <临时项目> lint --savedir <临时存档目录>
```

上述交叉验证仍不调用独立 `compile`。导出验证采用更强的隔离边界：完整复制 SDK，并只把输入
项目源脚本与独立导出的 `.rpy` 合并到另一个临时项目。从临时 SDK 只允许执行：

```text
<临时 SDK>/renpy.exe --version
<临时 SDK>/renpy.exe <临时项目> lint --savedir <临时存档目录>
<临时 SDK>/renpy.exe <临时项目> compile --savedir <临时存档目录>
```

lint 后先删除临时项目的 `.rpyc/.rpymc`，再执行 compile 并检查每个项目与翻译源脚本的编译
文件，因此 lint 的隐式编译不能冒充独立 compile 成功。验证不从已安装 SDK 执行任何命令，
Ren'Py 对 `renpy/common` 的强制重编译只会写入临时 SDK 副本。

启动显示验证复用同一完整临时边界，只额外允许：

```text
<临时 SDK>/renpy.exe <临时项目> run --savedir <临时存档目录>
```

启动进程的 `APPDATA`、`LOCALAPPDATA`、`TEMP` 和 `TMP` 也指向临时根，并通过
`RENPY_LANGUAGE` 选择待验证语言。stdout/stderr 单独写入临时日志；项目日志、缓存、编译物、
存档和可能的截图只能位于临时 SDK、项目、存档或隔离用户数据目录。CI 不需要 SDK 或图形桌面，
使用受控替身验证命令、窗口证据和进程收尾状态机。
