# GalTrans 产品愿景

## 目标

GalTrans 最终是一套面向普通玩家的本地优先视觉小说个人汉化工具。玩家选择自己合法持有、
且被 GalTrans 明确支持的生肉游戏后，工具在独立工作区中提取文本、恢复剧情上下文、生成和
自动检查译文，并生成可单独启动和持续修正的个人汉化副本；逐条审阅是可选改进而不是默认
前置步骤。目标体验是让玩家
像游玩已有汉化的游戏一样使用该副本，而不是要求玩家理解脚本、Python 或命令行。

汉化组和独立开发者也可以使用同一套确定性处理与审阅能力，但当产品设计发生取舍时，优先
保证非程序员玩家能够理解、恢复和安全完成流程。

它不是“让模型直接改游戏文件”的工具。游戏资源处理必须由确定性程序完成，模型只参与
语言理解、翻译建议、风格调整和语义质检。

## 最终能力方向

- 通过插件支持多个视觉小说引擎，首个引擎为 Ren'Py。
- 自动识别游戏引擎和受支持范围；无法安全处理时给出明确原因，而不是猜测或强行继续。
- 把用户选择的游戏目录保持为只读输入，所有转换、缓存和运行验证都在独立工作区或副本中完成。
- 建立角色、称谓、术语、场景、路线和上下文模型。
- 支持云端与本地模型，并提供缓存、重试、费用和隐私控制。
- 提供初译、自动重试、一致性检查和低置信度报告；后续可选人工复核不阻塞默认自动流程。
- 保护变量、文本标签、跳转、控制符、编码和原始文件。
- 支持增量处理、差异审阅、撤销和可追踪的操作记录。
- 检查漏译、错位、术语冲突、文本溢出和脚本损坏。
- 后期支持图片文字、字体、UI 和有限的游戏内自动验证。
- 为受支持的游戏生成可启动的独立个人汉化副本；专业用户仍可导出翻译资源或差分补丁。

## 目标用户

- 首要用户：希望把自己合法持有的生肉视觉小说制作成个人汉化版本的普通 Windows 玩家。
- 次要用户：需要减少重复劳动并保留人工审阅权的个人汉化者和汉化组。
- 次要用户：希望为自己的游戏生成和验证中文资源的独立开发者。

首要用户不应被要求安装 Python、执行命令、修改游戏脚本或理解引擎目录结构。关键操作必须
提供清晰提示、安全默认值、失败恢复和结果报告；不要求玩家逐条判断译文才能生成初版副本。

## 非目标

- 不承诺无人参与即可达到优秀人工汉化的文学质量。
- 不以破解 DRM、绕过加密或未经授权分发游戏内容为目标。
- 不承诺一个通用解析器自动支持所有私有或魔改引擎。
- 不把 OCR、Hook 或游玩时覆盖字幕作为首个正式版的主要路线。
- 不让语言模型直接拥有不受校验的文件写入权限。
- 不在早期版本同时支持解包、图片修复、多人协作和所有引擎。

## 成功标准

对一个明确支持、由用户合法持有且允许本地处理的游戏，普通 Windows 玩家无需接触 Python、
命令行或游戏脚本即可完成：

```text
选择游戏 → 兼容性检查 → 自动翻译与质检 → 生成独立汉化副本 → 启动验证
```

生成的副本可以像普通汉化游戏一样重复启动，并可在 GalTrans 中继续修正译文。每一步可以
中断、恢复和审计；任何自动化失败都不会修改或破坏原始游戏。不受支持或需要绕过保护的游戏
必须在写入前停止，并说明限制。
